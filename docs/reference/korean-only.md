# 앱은 한국어만 그린다 (2026-09-07)

## 무엇을 바꿨나

앱 화면 문자열에서 영어·일본어를 걷어냈다. 예전에는 문구 하나가 세 칸(`t(한국어, 영어, 일본어)`)
이었고, 사용자가 설정에서 언어를 고르면 그중 한 칸이 나왔다. 지금은 한국어 문자열 하나만 있다.

- `L.t(ko, en, ja)` — 삭제. 화면 문자열은 한국어 리터럴이다.
- `AppLanguage`(ko·en·ja) — 삭제. 설정의 언어 선택 항목도 함께 없앴다.
- 세이브의 `language` 항목 — 삭제. 예전 세이브에 남아 있어도 읽지 않고 버린다(모르는 항목은
  원래 무시하므로 별도 이전 절차가 필요 없다).

## 왜 바꿨나

세 칸을 채우는 비용이 실제 사용자보다 컸다. 문구 하나를 고칠 때마다 세 언어를 함께 고쳐야 했고,
"두 칸만 채워 일본어 사용자에게 영어가 나가는" 부류의 결함을 막으려고 별도 가드 테스트까지 두고
있었다. 그 가드(`LanguageSplitGuardTests`)는 이제 필요 없어 함께 지웠다 — 지키던 성질 자체가
사라졌기 때문이다.

## 그래도 다국어가 남는 자리

**PokéAPI 데이터.** 포켓몬·기술·특성 이름과 설명은 우리가 쓴 글이 아니라 PokéAPI 가 언어별 표로
주는 값이다. 표는 그대로 받고, **읽을 때 한국어 칸을 고른다.** 그 규칙은 `PokemonNaming` 한 곳에
있다.

- `PokemonNaming.name(_:)` — 한국어가 없으면 **영어로 폴백한다.** 한국어 이름이 없는 종·기술이
  실제로 있고, 그때 이름을 비우면 화면에 `#25` 같은 번호만 남는다.
- `PokemonNaming.prose(_:)` — 설명 문장은 기본적으로 **폴백하지 않는다.** 영어 설명을 통째로
  내보내면 포켓몬의 말투가 한국어 밖으로 새어 나간다. **특성만 예외**(`allowEnglishFallback:
  true`, 2026-09-08) — 특성 설명은 페르소나 대사가 아니라 전투 규칙 정보라, 최신 세대 특성처럼
  PokéAPI 한국어 flavor text 가 아직 없을 때 이름만 뜨고 설명이 통째로 비는 것보다는 영어라도
  보여 주는 쪽이 낫다.

**LAN 으로 오가는 표.** `MoveSpec.names` 는 언어별 표 그대로 다른 기기에 전달된다. 표를 한 칸으로
줄이지 않는다 — 줄이면 옛 버전과 프레임 모양이 어긋난다.

**README·랜딩 페이지.** 앱 밖의 소개 자료라 en/ko/ja 다국어를 그대로 둔다(`CLAUDE.md` 기여 언어
규약 참조).

## 새 문구를 넣을 때

한국어 문자열을 그대로 쓴다. 두 화면 이상이 같은 문구를 쓰면 그때 `L` 의 이름 붙은 프로퍼티로
승격한다 — 일회성 문구까지 올리면 `Localization.swift` 가 뒤덮인다.

## 옛 문서를 읽을 때

`docs/reference/defect-log.md` 에는 이 전환 이전에 쌓인 항목이 많고, 그중 상당수가 `AppLanguage`·
"세 언어" 를 전제로 쓰여 있다. **지난 결함의 기록이지 지금의 규칙이 아니다** — 지우지 않고 그대로
두되, 현재 동작은 이 문서를 따른다.
