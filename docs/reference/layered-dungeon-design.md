# 층 던전 — 판 길이를 구조로 잠그는 재설계

기존 설계는 [`puzzle-dungeon-design.md`](puzzle-dungeon-design.md) 다. **맵 생성 부분은 이 문서가
대체한다.** 하루 한 판·날짜 결정론·첫 클리어만 보상·안개 같은 뼈대는 그대로 간다.

## 왜 바꾸나 — 한 판이 평균 2클릭이었다

365일 맵을 전수로 재보니 시작 방에서 보스까지 **최단 클릭 수가 평균 2.1** 이었다.

```
1클릭 49일 · 2클릭 229일 · 3클릭 84일 · 4클릭 2일 · 5클릭 1일
최단 경로 체력 소모 평균 38 / 예산 100  → 예산이 제약이 아니다
```

척추(시작→보스 경로)는 의도대로 6~8방으로 깔린다. 그런데 **여분 간선이 그 척추를 통째로
우회한다.** 여분 간선 수를 "버린 간선의 11~19%"로 잡은 것이 원인이다 — 방 14개 완전그래프의 버린
간선은 78개라, 그 15%가 11개다. 최소 신장 트리 간선 수(13)와 같은 규모라 **트리에 간선을 두 배로
얹는 셈**이고, 그래프 지름이 2~3으로 무너진다.

기존 설계 문서에 이미 증거가 적혀 있었다 — "여분 간선이 지름을 3~4방으로 줄여 완성된 그래프에서
최단경로로 척추를 찾으면 6방을 만들 수 없었다". 그 발견이 "척추를 먼저 뽑자"는 해결로만 흘러가고,
**지름이 3~4라는 사실 자체가 판 길이 문제**라는 데까지 가지 않았다. 테스트도 여분 간선 비율과
클리어 가능성만 잠갔고 **판 길이를 재는 테스트가 없었다.**

## 구조 — 왼쪽에서 오른쪽으로만

```
        1층    2층    3층    4층    5층    ...   12층
본선     o ───── o ───── o ───── o ───── o ─── … ── ★
                 │              │
곁방             ?              ?
```

- **본선**: 층을 왼쪽에서 오른쪽으로 넘어가는 길. 층마다 방이 1~2개이고, 다음 층의 방으로만 간선이
  간다. **왼쪽으로는 못 간다.**
- **곁방**: 본선 방에 옆으로 하나 매달린 막다른 방. 들어가면 왔던 통로로 되나오는 수밖에 없어
  통로 비용을 두 번 낸다.
- **보스**: 마지막 층의 방 하나.

이 구조의 값은 **판 길이가 구조에서 나온다**는 것이다. 진행 방향이 한쪽뿐이라 보스로 가는 지름길이
존재할 수 없고, 최단 클릭 수 = 층 수 − 1 로 확정된다. 지금 결함이 재발할 여지가 없다.

## 확정 치수

| 항목 | 값 | 근거 |
|---|---|---|
| 층 수 | 12 | 최단 11클릭. 곁방 두세 개를 들르면 15~17클릭이라 한 판 2~4분 — 설계 목표(5분 안쪽)에 처음으로 맞는다 |
| 층당 본선 방 | 1~2개 (첫 층·마지막 층은 1개) | 2개면 "어느 문으로 갈까"가 남고, 3개 이상은 화면 목록만 길어진다 |
| 곁방 | 사이 층의 방마다 1/2 확률 (실측 평균 7개) | 매 층 판단이 있으면 지겹고, 없으면 전진만 남는다 |
| 방 총수 | 평균 24개 · 상한 32개 | 이름 풀을 32개 이상으로 늘려야 한다(지금 16개) |
| 기본 체력 예산 | 100 (그대로) | 모두 같은 값이라 같은 맵이 같은 난이도다 |
| 본선만 따라갔을 때 남는 체력 | 5를 목표로 배분 (실측 평균 10) | 기존 15에서 조인다. 남는 체력이 곧 곁방을 열 밑천이라 여기가 곧 곁방 예산이다 |
| 보스 데미지 | 30 (그대로) | 가장 깊은 방의 무게 |
| 첫 클리어 보상 | 별의조각 1,000 (그대로) | 곁방 보상과 급이 갈려야 한다 |

## 곁방 내용 — 꽝이 있어야 판단이다

| 내용 | 비율 | 값 |
|---|---|---|
| 회복의 샘 | 25% | 체력 +20 |
| 보물 | 30% | 별의조각 60~150 |
| 빈 방 | 20% | 꽝 — 왕복 통로 비용만 날린다 |
| 교전 | 25% | 꽝 — 왕복 비용에 데미지 8~25 |

기대값을 보면 이 거래의 성격이 드러난다(왕복 통로 3 기준):

```
체력 기준   +20×0.25 − 16.5×0.25 − 3  =  −2.1   손해
보상 기준   별의조각 0.30 × 100        =  +30    이득
```

**체력을 팔아 별의조각을 산다.** 체력이 남으면 사는 게 맞고 빠듯하면 지나치는 게 맞다 — 이것이 매
층의 판단이다. 곁방을 전부 털면 하루 평균 237 별의조각이지만 체력이 그걸 허락하지 않는다(남는
체력 10이면 곁방 두세 개가 한계). 무엇을 열지 고르는 것이 이 게임이다.

**회복의 샘은 본선에 두지 않는다.** 본선에 있으면 지나가다 공짜로 마시는 것이라 판단이 없고, 기존
설계에서 척추 여유가 15에서 35로 뛴 실측이 그 이유였다.

**꽝이 기억에 값을 만든다.** 첫 판에 3층 곁방을 열어 꽝을 맞으면, 그 손해가 다음 판에 3층을 그냥
지나칠 근거가 된다. 설계가 처음부터 말한 "첫 시도는 정찰, 두 번째가 최적화"가 여기서 처음으로 실제
작동한다 — 최단 2클릭이던 시절에는 기억할 것도 최적화할 것도 없었다.

## 본선 교전은 층 단위로 배치한다

한 층의 방 일부에만 교전을 두면 **교전 없는 쪽으로 새어** 예산 압박이 사라진다(실측: 남는 체력이
5 목표인데 25가 나왔다). 층 전체에 같은 데미지를 두면 어느 경로로 가도 그 층의 교전을 정확히 한 번
만난다.

- 교전을 두는 층은 사이 층의 절반이다. 나머지 층은 빈 방이라 숨 돌릴 구간이 남는다.
- 배분 기준은 **가장 비싼 전진 통로 합**이다. 가장 싼 경로 기준으로 잡으면 비싼 경로를 고른 날
  클리어 불가가 나온다.
- 배분식: `100 − 여유 5 − 가장 비싼 전진 통로 합 − 보스 30` 을 교전 층 수로 나눈다.

365일 전수 실측: **클리어 불가능한 날 0일**, 본선 최선 경로로 클리어했을 때 남는 체력 평균 10.

## 화면에 미치는 영향

이번에 넣은 화면 뼈대([`puzzle-dungeon-design.md`](puzzle-dungeon-design.md) 의 화면 절)는 그대로
쓴다. 층 구조라 오히려 더 잘 맞는다.

- 좌표의 `x` 가 곧 층이라 **출구 방위가 의미를 갖는다** — 오른쪽(→)이 전진, 위아래(↑↓)가 곁방이다.
- 진행 표시를 `기억 n/총방수` 대신 **`3층 / 12층`** 으로 바꾼다. 층이 곧 진행도다.
- 되돌아가기 목록은 곁방에서 나오는 한 줄만 남는다. 본선은 되돌아갈 수 없다.
- 방 이름 풀을 16개에서 **32개 이상**으로 늘린다(방 상한 32). 늘리기 싫으면 "3층 위쪽 길" 같은 위치
  표기로 바꿔야 하는데, 이름 쪽이 기억에 남아 재도전에 유리하다.
- 곁방 줄에는 **왕복이라는 사실**이 보여야 한다(들어가면 되돌아 나와야 한다는 것). 안 보이면 전진
  통로와 같은 값으로 읽힌다.

## 세이브에 미치는 영향

`DungeonProgress` 구조는 그대로 두되 두 가지를 고친다.

- `normalize()` 의 방 번호 검사가 `0..<14` 고정이다. **방 수가 날마다 다르므로** 그날 맵의 방 수로
  검사해야 한다.
- 곁방 보물은 **하루 한 번만** 준다. 재도전으로 같은 보물방을 다시 털 수 있으면 하루 상한이 무의미해
  진다. `DungeonProgress` 에 그날 수확한 보물방 번호를 남긴다.

## 테스트 범위

기존 테스트 중 **판 길이·구조에 관한 것은 전부 다시 쓴다.**

- 같은 날짜 키 → 같은 맵, 다른 날짜 → 다른 맵 (그대로)
- **모든 간선이 층을 정확히 하나 넘는다** — 왼쪽으로 가는 간선이나 층을 건너뛰는 간선이 없다
- **곁방은 막다른 길이다** — 곁방에서 나가는 간선이 들어온 통로 하나뿐
- **최단 클릭 수가 층 수 − 1 로 고정** — 365일 전수. 지금 결함을 직접 겨냥하는 테스트다
- 모든 층의 모든 방이 시작 방에서 도달 가능
- **365일 전수 클리어 가능** — 가장 비싼 전진 경로로도 예산 100 안에 보스를 넘는다
- 본선 교전이 층 단위로 배치된다 — 한 층 안에서 교전을 피해 가는 경로가 없다
- 곁방 내용 분포가 목표 비율의 ±5%p 안 (365일 집계)
- 안개: 들어가기 전에는 곁방 내용이 밝혀지지 않는다
- 보물은 하루 한 번 — 같은 보물방을 두 번째로 밟으면 0
- 체력 0 → 실패, 보스 방 생존 → 클리어 (그대로)

새 조건 분기를 넣을 때 커버리지 퍼센트를 증거로 삼지 않는다. `xcrun llvm-cov show … --show-regions`
로 해당 블록이 한 번도 실행되지 않았는지(`^0`) 직접 본다.

## 범위 밖

- **연출·대기 시간.** 클릭이 즉시 처리되는 것은 그대로 둔다. 판 길이는 구조로 늘린다.
- **1:1 레이스.** 같은 날짜 맵을 두 사람이 동시에 푸는 후속 작업. 층 구조라 진행도 비교가 쉬워진다
  (몇 층까지 갔나) — 오히려 이 재설계 뒤에 하는 편이 낫다.
- **곁방 보물의 아이템화.** 지금은 별의조각만 준다. 아이템을 섞으면 하루 상한 설계가 따로 필요하다.
