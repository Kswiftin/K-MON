# Memory Home 고도화 계획 (기획서 27항 → 이 앱의 범위)

원본 기획서는 `docs/product/pokemon-my-mini-home-idea.md` 다(추적되지 않는 경로 —
`.gitignore` 가 `docs/product/` 를 무시한다. 그래서 **결정과 근거는 이 문서에** 남긴다).

## 이 앱은 기획서의 어느 부분을 할 수 있나

기획서는 오픈월드 생활형 RPG 를 상정한다. 이 앱은 **메뉴바 포모도로 + 동행**이다. 그래서
"동네를 걷는다·야생을 만난다·NPC 와 교환한다" 계열(§2 §6 §7 §21 §22 §23 §26)은 새 게임을
만드는 일이고, 이 계획의 범위가 아니다.

범위 안은 기획서 §27 이 스스로 고른 ★★★★★ 세 개다 — **미니홈피/미니룸 정체성**,
**포켓몬 생활 AI**, **사진/추억 앨범**. 셋 다 이 앱에 이미 데이터가 있다.

## 설계 원칙: 새 저장 필드를 만들지 않는다

이 홈의 기존 코드가 반복해 지키는 규칙이다 — POKÉLOG 는 "read-time view of the existing
album", 계절은 "달력 월에서 파생하므로 저장 필드가 하나도 없다", 일기는 "저장하지 않는다".

파생으로 만들면 (1) 세이브 마이그레이션이 필요 없고 (2) 기존 사용자의 홈이 즉시 풍부해지며
(3) 되돌리기가 삭제 한 번이다. **이 계획이 더한 모든 단계가 파생이다.** 새 `Codable` 키는 0개다.

한 곳만 예외이고, 방향이 반대다 — 5단계(BGM 제거)는 **있던 키를 없앤다**. 원칙을 깨는 게 아니라
같은 원칙의 뒷면이다: 키가 적을수록 이전도 되돌리기도 싸다. 다만 함정은 반대쪽에 있다 —
새 키는 "옛 세이브에 없음" 을 다루지만, 지운 키는 "옛 세이브에 남아 있음" 을 다뤄야 한다.

## 단계

### 0단계 — 도달 불가 기능 복구 (§14 §17 §24 §25)

`eee5c86` 이 팝오버 `MemoryHomeView` 를 창 `MemoryHomeWindowView` 로 옮기면서 일부만 이식했다.
남은 쪽은 `@available(*, deprecated)` + **비-`View`** 로 박제돼, 다음 다섯 기능이 코드에는
있는데 화면에서 사라졌다.

| 기획서 | 기능 | 박제된 위치 |
|---|---|---|
| §14 | 파도타기 | `MemoryHomeVisitSheet` |
| §17 | 기분 → 동행 반응 문구 | `MemoryHomeMoodStyle.reaction` |
| §24 | 계절 배지 | `MemoryHomeSeasonStyle` |
| §25 | 계절 결산 | `seasonRecap` + `MemoryHomeSeasonRecapSheet` |
| §5 | **방꾸미기 전체** — 스타일 4종·12칸 격자·되돌리기·초기화 | `MemoryHomeView.furnitureRow` |

마지막 줄이 이 결함의 핵심이다. 방꾸미기는 `9de278f` 가 새로 넣은 기능인데, **같은 커밋이
만든 새 창이 아니라 그 커밋이 밀어낸 옛 화면에** 붙었다. 그래서 최신 기능이 한 번도 도달
가능한 적 없이 릴리스됐고, 창에는 legacy 3슬롯만 남아 있었다.

**왜 테스트가 못 걸렀나**: 테스트는 스타일 헬퍼의 세 언어 문구와 앨범 메서드의 지속성을
직접 호출해 검증한다. 둘 다 통과한다 — 호출자가 화면이 아니어도 통과하기 때문이다.
"이 기능에 도달할 수 있는가" 를 묻는 검증이 없었다.

**영구 캡처**: 박제된 `MemoryHomeView` 를 **삭제**했다(약 630줄). 살아 있는 창이 쓰는 시트
둘(스티커 사진·계절 결산)만 남기고, 창이 이미 인라인으로 대체한 시트 셋(POKÉLOG·다이어리·
방문)은 함께 지웠다. 문서나 기억이 아니라 구조로 막는다 — 죽은 두 번째 홈 화면이 없으면
기능이 그쪽에 남는 일 자체가 불가능하다.

더해서 `test-gate.sh` 에 `Sources/PokeTokenBar/UI` 의 `@available(*, deprecated` 를 실패로
만드는 grep 게이트를 넣었다. 테스트로는 못 막는 부류라서다(위 문단 참조).

**§11 주크박스는 이후 통째로 제거했다** — 5단계를 보라. 이 표에 한 줄 남아 있던 시기가 있었으나
복구 대상이 아니다.

**부수 발견**: 방꾸미기를 창으로 옮기면서 R7 → R8 이전이 legacy `roomLayout` 을 비우지 않아,
방을 초기화하고 재시작하면 옛 가구가 되살아나는 결함을 찾아 고쳤다. 자세한 내용과 부류는
`defect-log.md` 의 "일회성 이전은 일회성이 아니다" 항목에 있다.

### 1단계 — §5 포켓몬 생활 AI (종 × 가구 반응)

기획서가 ★★★★★ 로 꼽고 예시까지 준 항목인데, 구현은 가구 3종만 보는 문구 3줄이었다
(`roomInteraction`). 종을 아예 보지 않아 "누구의 방이든 같은 문장" 이었다.

`MemoryHomeRoomLife` (순수 함수, 게이트 대상)로 뺀다. 우선순위는 좁은 것부터:

1. **종 × 가구** — 기획서의 짝을 있는 가구로 옮긴다(잠만보+침대 → 침대 독차지,
   피카츄+레트로 TV → 화면 위에서 잠, 고오스+TV → 화면에서 튀어나옴 …).
2. **가구 단독** — 짝이 없는 종의 기존 3줄.
3. **기분** — 가구가 비었으면 §17 반응이 방을 채운다.
4. **계절** — 그것도 없으면 계절 한 줄.

입력은 전부 이미 저장된 값이다: `speciesID`, `placedDecor`, `moodByDayKey`, 달력.

### 2단계 — §13 동행이 방명록에 흔적을 남긴다

`companionGuestbookLine` 은 이미 쓰여 있었지만 호출자가 없었다. 기획서는 "아주 드물게" 라
했으므로 **dayKey 결정론**으로 만든다 — 난수면 열 때마다 다르고, 캡(50개)을 잠식한다.

- 하루 최대 1개. 같은 날 동행 글이 이미 있으면 아무것도 하지 않는다(멱등).
- dayKey 해시로 약 4일에 1번. 같은 날 다시 열어도 결과가 같다.
- 문구는 그날의 기분을 읽는다 — 우울한 날 "오늘 진짜 신났어!" 가 뜨면 §17 을 배신한다.

### 3단계 — §18 계절·기념 추억 카드

카드는 6종(첫 만남·집중·진화·1주년·함께한 N일·방문)뿐이고 전부 "적립" 계열이다.
기획서가 든 예(첫눈·크리스마스)는 **날짜**가 만드는 카드다.

- `firstSnow` — 겨울에 남은 첫 기억. `christmas` — 12/25 에 남은 기억.
- 둘 다 이미 있는 `memories[].createdAt` 만 읽는다. 생일은 넣지 않는다 —
  트레이너 생일을 저장한 적이 없고, 그걸 묻는 것은 이 계획의 "새 필드 0개" 를 깬다.

### 4단계 — §25 연말 결산

기획서가 "대표 기능으로 밀어도 좋다" 고 한 항목인데, 있던 것은 계절 결산뿐이었다.
`yearRecap` 이 한 해를 한 장으로 되돌려 준다 — 만난 동행, 가장 많은 **날**을 함께한 동행,
함께한 날 수, 올해의 기억·사진, 그리고 "내년에도 같이 놀자."
(대표 BGM 한 줄도 있었으나 5단계에서 곡과 함께 내렸다.)

- 창은 `dayKey` 의 앞 4글자다. `Date` 산술로 연초/연말을 만들면 타임존·DST 에서 하루가 어긋난다.
- **담지 않은 셋.** 담을 수 없는 것을 담으면 결산이 거짓말을 한다:
  집중 횟수(`completedFocusSessionIDs` 에 날짜가 없다), 기분(`moodByDayKey` 가 60일에서 잘린다),
  기획서의 "가장 자주 방문한 장소"(이 앱에 장소가 없다).
- 자동으로 띄우지 않는다. "올해 한 번만" 판정은 새 저장 필드를 요구하고, 그건 이 계획의
  "새 필드 0개" 를 깬다. RECORDS 탭의 버튼으로 연다.

**같이 고친 결함 3건** (전부 "파생 통계가 라벨과 어긋난다" 부류):

| 무엇 | 어긋남 | 처방 |
|---|---|---|
| `seasonRecap.memoryCount` | 숨긴 기억을 셌다 (`timeline`·`diary`·날짜 카드는 전부 제외하는데) | `!isHidden` 필터 |
| `seasonRecap.mostChosenMood` | 동률에서 딕셔너리 순회 순서를 따라가 호출마다 답이 바뀜(실측) | rawValue 사전 순 타이브레이크 |
| `seasonRecap.focusSessions` | **통산값**이 "이번 계절" 라벨 아래 있었다 | 좁힐 수 없으므로 라벨에 "통산" 을 적음 |

**영구 캡처**: `test-gate.sh` 에 **도달 불가 시트 스윕**을 넣었다 — `MemoryHome*Sheet` 중
아무도 `.sheet` 로 띄우지 않는 타입이 있으면 실패한다. `deprecated` 게이트의 형제다(계절 결산
시트가 정확히 이 형태로 죽어 있었다). 결함을 주입해 실제로 실패하는지 확인했다.

### 5단계 — §11 주크박스(대표 BGM) 제거

**넣은 기능을 뺀 첫 단계다.** 판단 근거는 "이 홈의 핵심 셋(미니룸 정체성·생활 AI·사진/추억
앨범)에 기여하는가" 하나다. 주크박스는 셋 중 어디에도 속하지 않았고, **오디오를 재생하지
않으므로** 남는 것은 화면에 걸린 곡 이름 하나였다. 해금이 기억에서 파생된다는 설계는 좋았지만,
그 설계가 지키던 대상이 없다.

- 지운 것: `MemoryHomeJukebox`(64줄)·`MemoryHomeJukeboxTrack`·`setJukeboxTrack`·프레젠터 BGM
  섹션·`yearRecap.jukeboxTrack`·전용 테스트 파일. 삭제 206줄 / 추가 41줄.
- **저장 필드는 0개가 아니라 −1개다.** 이 계획의 다른 모든 단계가 "새 키를 만들지 않는다" 인 데
  반해 이 단계는 있던 키(`memoryHomeAccess.jukeboxTrack`)를 **없앤다**. 그래서 방향이 반대인
  호환 문제가 생긴다 — 마이그레이션이 아니라 **이미 배포된 세이브에 남아 있는 키를 만나는 쪽**이다.
  키드 컨테이너는 모르는 키를 무시하므로 그대로 열리고, 다시 저장하면 파일에서도 사라진다.
- **LAN 은 건드리지 않았다.** 착수 전엔 방문 광고 페이로드에 곡이 실린다고 봤는데, 실제로 그
  값은 와이어에 나간 적이 없었다(`yearRecap` 안에만 있었다). 프로토콜 호환 작업이 필요 없었다.
- 회귀 테스트 2개를 남겼다: 구 세이브가 손실 없이 열리는가(`.corrupt` 백업 부재로 판별),
  재저장 시 은퇴한 키가 다시 쓰이지 않는가. 첫 번째를 쓰다가 기존 테스트의 세이브 픽스처가
  **한 번도 디코딩된 적 없었다**는 것을 찾았다 — `defect-log.md` 의 "세이브 픽스처가 디코딩에
  실패해도" 항목.

### 6단계 — §5 생활 AI 축 확대 (룸메이트·하루)

1단계가 만든 `MemoryHomeRoomLife` 를 넓혔다. 짝 표가 8줄뿐이라 대부분의 방이 가구 단독 문구로
떨어졌고, 같이 사는 동행이 있어도 문장은 한 마리만 봤다.

- 우선순위: **종×가구 → 룸메이트 → 가구 → 기분 → 하루(아침·밤) → 계절(낮)**.
  룸메이트가 가구보다 앞인 이유는 1단계와 같다 — "둘이 같이 있다" 는 이 방에만 있는 사실이고,
  가구 단독 문구는 같은 가구를 놓은 모든 방이 공유한다.
- 짝 표 8 → 17짝. **가구 12종이 전부 최소 한 짝을 갖는다**(테스트가 게이트). 한 종류라도 비면
  그 가구를 산 사용자만 계속 일반 문구를 보는데, 화면에서는 "내 가구만 반응이 없다" 로 읽힌다.
- 새 `MemoryHomeTimeOfDay`(아침·낮·밤). 밤은 21시~5시로 **자정을 가로지른다** — 계절의 겨울이
  `default` 로 12·1·2 를 받는 것과 같은 부류다.
- 새 저장 필드 0개. 입력은 `speciesID`·`placedDecor`·`roommateIDs`·`moodByDayKey`·시계다.
- **함정**: `timeOfDay` 는 함수 안에서 시계를 읽지 않고 **인자로 받는다**. 안에서 읽으면 밤에
  돌린 CI 만 빨개진다(기존 계절 테스트가 정확히 그 함정에 걸릴 뻔해 `.day` 를 명시하게 고쳤다).
- **함정**: 룸메이트 문구는 이름 뒤에 "와/과" 를 안 쓴다. 받침으로 갈리는 조사인데 동행 이름은
  사용자가 짓는 값이라 받침을 알 수 없다(별명이 이모지 하나여도 성립해야 한다).

### 7단계 — §24 미니룸 창밖 시각

방이 하루 내내 같은 그림이었고 계절은 대문 배지로만 보였다. 벽에 창을 하나 걸고 **유리만**
시각에 따라 배색한다.

- 창틀은 스타일 램프(`1`~`4`), 유리는 새 **시각 램프**(`g`~`k`). 두 램프를 갈라 둔 것이
  "방 테마는 시간에 안 변하고, 하늘은 테마에 안 변한다" 의 근거다.
- 새 저장 필드 0개. 시계에서만 파생하며 4스타일 × 3시각 = 12장을 미리 그려 캐시한다.
- **`TimelineView` 를 쓰지 않는다.** 매초 갱신하면 미니룸이 열려 있는 내내 상시 애니메이션이
  된다(`defect-log.md` 의 상시 표시 성능 부류). 방을 다시 열 때 반영되면 충분하다.
- **테스트를 이미지가 아니라 격자로 건다.** "테마는 시간에 안 변한다" 를 이미지로 검사하면
  가구 API 가 시각 인자를 안 받으니 무조건 통과하는 공허한 테스트가 된다. 진짜 근거는
  "창 말고는 시각 램프 문자를 쓰는 격자가 없다" 이고, 그것을 전수 검사한다.

### 8단계 — §18 추억 카드 3종 추가

날짜 카드가 첫 겨울·크리스마스 둘뿐이었다. 셋을 더한다 — 전부 `memories[].createdAt` 파생이고
새 `Codable` 키가 0개다.

- `newYear`(1/1 의 첫 기억) · `allFourSeasons`(**네 번째 계절을 채운 그 기억**의 날짜) ·
  `memoryStreak(7 | 30)`(연속으로 기억을 남긴 날).
- **연속은 총량이 아니다.** 기존 적립 카드(`focusSessions`·`togetherDays`)는 총량이라 하루도
  빠짐없이 세지만, 연속은 끊기면 0으로 돌아간다. 같은 7개라도 흩어져 있으면 카드가 없어야
  하므로, 두 케이스를 나란히 보는 테스트가 없으면 `count >= 7` 구현이 그대로 통과한다.
- 하루에 여러 개를 남겨도 하루로 접는다(`dayKey`). 이어짐 판정은 `startOfDay` 사이 일수 차로
  한다 — 초 단위 뺄셈(`86_400`)이면 서머타임이 있는 지역에서 연속이 끊긴다.
- 숨긴 기억(`isHidden`)은 카드를 만들지도, 연속을 잇지도 않는다. `seasonRecap.memoryCount` 가
  숨긴 기억을 세던 4단계 결함과 같은 부류다.
- **같이 고친 것**: 크리스마스 판정이 `Calendar.current` 를 써서 이 기능 안에 달력이 둘이었다.
  스윕이 `MemoryHomeSeason.current` 와 `seasonRecap` 에서 같은 부류를 더 찾아 셋 다
  `SeasonBoard.gregorian` 으로 통일했다 — `defect-log.md` 의 "한 기능 안에 달력이 둘이면".

### 9단계 — §14 파도타기와 방문의 나머지 절반 (쓰기만 하던 여섯 API)

0단계가 "박제된 화면"을 지웠지만, 방문 기능은 **화면이 없어서** 여전히 절반만 살아 있었다.
전송로(Bonjour·프레이밍·검증·카운터)는 멀쩡한데 Core 가 쓰는 값을 읽는 화면이 0곳이었다.

| 값·API | 화면이 없어서 생긴 결과 |
|---|---|
| `visitedHomeStamps` | 다녀온 홈 발자국이 화면에 없다 — §14 파도타기가 없던 실제 이유 |
| `recentRequesters` | 누가 다녀갔는지 모른다. TODAY/TOTAL 숫자만 올랐다 |
| `setMemoryHomeBlocked` | 방문자를 차단할 길이 없다 |
| `setPeerAlias` | 방문자에게 일촌명을 붙일 길이 없다 |
| `pin` + `setSharedPinnedMemory` | 카드의 `sharedMemoryBody` 가 **모든 릴리스에서 nil** |
| `setFeaturedPhoto` | 카드의 `featuredPhoto` 가 **모든 릴리스에서 nil** |
| `clearProfileMessage` | 한 번 적은 대문 문구를 내릴 길이 없다(덮어쓰기만 가능) |

- **파도타기는 새 저장 필드 0개다.** 다음 홈 선택과 발자국을 `MemoryHomeSurf`(순수 함수, 게이트
  대상)가 이미 저장 중인 도장에서 파생한다. 커서는 저장하지 않는다 — 창을 닫으면 처음부터 돈다.
- **"오늘 안 간 집 우선, 다 돌았으면 커서 다음"** 두 규칙이다. 둘째가 없으면 하루에 이웃을 다 돈
  사용자에게 버튼이 조용히 죽는다. 그 분기(A=false, B=true)를 단독으로 검증한다.
- **공유는 고정과 별개의 동의다.** 고정은 내 대문 장식이고 공유는 남에게 보내는 일이라, 대문
  문구가 `sharesProfileMessage` 를 따로 두는 것과 같은 규칙을 쓴다.
- **발자국은 와이어에 나가지 않는다.** 방명록과 같은 취급이며 화면에도 그렇게 적었다.
- **왜 테스트가 못 걸렀나**: 앨범 메서드의 지속성과 프로토콜 클램프를 직접 호출해 검증하는
  테스트가 38개 있었고 전부 통과했다 — 호출자가 화면이 아니어도 통과하기 때문이다. 0단계와
  **같은 부류의 재발**이고, 그때 넣은 게이트 둘은 타입(`deprecated`·고아 시트)만 보지 필드와
  mutator 는 보지 않았다.
- **영구 캡처**: **호출부 없는 mutator 스윕**을 넣었다 — `save()` 를 부르는 비-private 함수 중
  아무도 부르지 않는 것이 있으면 실패한다. 결함을 되돌려 실제로 실패하는지 확인했다. 잡는
  범위는 "호출부 0곳" 하나이고, 마운트되지 않은 뷰 멤버 안의 호출은 못 잡는다(그 형태를 grep
  으로 근사하려다 오탐이 쏟아져 접었다 — 게이트 주석에 남겼다). 그 뒤 범위가 `Sources/`
  전부로 넓어지고(#225), 판정이 이름 산술에서 **선언 위치**로 옮겨졌다(#233) — 지금 스윕은
  `scripts/mutator-sweep.sh` + `Tools/MutatorGate`(인덱스 스토어)이고, 결함 주입 대조는
  `scripts/verify-mutator-gate.sh` 가 종료코드로 남긴다.
- **남긴 것 둘**(allowlist, 이유 포함): `setHidden` 은 기억 관리 화면의 공백이라 방문과 분리했다 —
  `isHidden` 이 늘 false 이므로 결산·연속 카드의 `!isHidden` 필터가 전부 무동작이다. `setTheme` 은
  R8 `roomStyle` 이 대체했고 와이어 필드만 구버전 호환으로 남아 있다.
- **같이 찾은 테스트 위생 결함**: 기억 앨범은 상태 파일 *옆에* 산다(`CompanionStore.init`).
  상태 파일만 유일하게 하고 공용 temp 디렉토리에 두면 모든 테스트가 앨범 파일 하나를 공유하고,
  `swift test` 실행 **사이에도** 남는다. 새 테스트는 스토어마다 디렉토리를 판다.
