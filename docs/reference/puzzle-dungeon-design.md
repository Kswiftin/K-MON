# 하루 한 판 결정론 퍼즐 던전 (#79)

> **맵 생성 부분은 대체됐다 (2026-08-25).** 시작 방에서 보스까지 최단 2.1클릭이라 한 판이 몇 초에
> 끝나는 것이 365일 실측으로 드러났다. 새 구조(왼→오른 층 그래프 + 1뎊스 곁방)는
> [`layered-dungeon-design.md`](layered-dungeon-design.md) 에 있다. 이 문서에서 지금도 유효한 것은
> 하루 한 판·날짜 결정론·첫 클리어만 보상·안개·화면 구성이다.

> 구현 계획(태스크 단위, 코드 포함)은 [`puzzle-dungeon-plan.md`](puzzle-dungeon-plan.md) 에 있다.

기존 모험(`AdventureRun`)은 지역을 고르고 10분~2시간을 기다렸다가 보상을 받는다 — **직접 할 게
없다.** 이 던전은 그 빈자리를 메운다. 하루에 한 개 맵이 모두에게 똑같이 열리고, 무작위가 전혀 없어서
플레이어가 푸는 문제는 운이 아니라 **방문 순서**다. "체력 예산 안에서 어떤 순서로 방을 돌면 가장
깊은 방까지 갈 수 있나."

시도 횟수는 무제한이고 보상은 그날 **첫 클리어 한 번만** 준다. 그래서 실패는 벌이 아니라 정보다 —
첫 시도는 정찰, 두 번째 시도가 최적화다.

## 확정된 규칙

| 항목 | 값 | 근거 |
|---|---|---|
| 방 개수 | 14개 고정 | 5분 안쪽 한 판. 나중에 최적 해를 계산하는 솔버를 넣어도 상한(16~18)에 여유가 있다 |
| 기본 체력 예산 | 100 | 모두 같은 값이라 같은 맵이 같은 난이도다 |
| 보정 상한 | 합계 **+10** | 구성적 생성이 남기는 여유(약 15)보다 작아야 퍼즐이 남는다 |
| 첫 클리어 보상 | 별의조각 1,000 (고정) | 일일 미션 합(800)과 같은 급, 알(20,000) 대비 20일 |
| 보스 | 가장 깊은 방의 대폭 데미지 한 줄 | 별도 교전 상태·UI 분기를 만들지 않는다 |
| 실패·이탈 | 시도만 버리고 맵 기억은 남긴다 | 재시도 시 이미 밟은 방은 정체가 보이고 새 방은 안개 그대로 |
| 진입 위치 | 배틀 탭 카드 → 팝오버 전체 점유 | 체육관 리그(`nav.showGymLeague`)와 같은 자리·같은 패턴 |

### 체력 보정 세 축

기준선은 항상 100이고, 보정은 **깎지 않고 더하기만** 한다(불리해도 기준선 유지).

| 축 | 값 | 이유 |
|---|---|---|
| 동행 파트너의 타입 상성 | +5 | 로스터를 들여다볼 이유를 만든다 |
| 입장 전 소모 아이템 | +3 (1회) | 크게 주면 "아이템 갈아넣기"가 최적 전략이 되어 퍼즐이 사라진다 |
| 트레이너 레벨 | +0~2 | 매일 같은 값이라 판단 요소가 아니다 — 존재감만 남긴다 |

합계가 10을 넘지 않으므로 예산은 100~110, 난이도 편차는 10% 안이다. "오늘 맵 어려웠다"가 사람들
사이에서 같은 뜻으로 통하고, 나중 1:1 레이스도 실력 비교로 남는다.

## 맵 생성 — 클리어 가능성을 구조로 보장

날짜 문자열(`CompanionStore.dayKey`, 로컬 달력 `yyyy-MM-dd`)을 해시해 `SplitMix64` seed 를 만든다
(`BattleModel.swift` 에 이미 있는 결정적 난수 생성기를 그대로 쓴다). 같은 날짜면 어느 기기에서나
같은 맵이 나온다.

1. **방 좌표 14개**를 격자 위에 뽑는다. 좌표는 통로 길이와 **출구 방위**를 만드는 데 쓰고, 지도로는
   그리지 않는다(`DungeonMap.coords` 에 남는다). 타일 지도를 그리지 않으니 통로 모양을 만들 필요가 없다.
2. **최소 신장 트리(MST)** 로 전부 잇는다.
3. **버린 간선의 10~20%를 되살린다.** 트리만 두면 순환이 없어 모든 가지가 막다른 길이고 되돌아오기밖에
   할 게 없다. 순환이 있어야 경로 선택이 실제 판단이 된다.
4. **구성적 배치** — 먼저 시작 방에서 보스 방까지 이어지는 척추 경로(6~8방)를 정하고, 그 경로만
   따라가도 기본 예산 100으로 여유 약 15를 남기고 도달하도록 회복·교전을 배치한다. 남은 방은 자유롭게
   채운다. 클리어 가능성이 구조에서 나오므로 최적 해를 계산하는 솔버가 필요 없다.

방 종류는 넷이다: 빈 방, 교전(고정 데미지), 회복의 샘(1회), 보스.

**구현에서 갈린 지점(2026-08-21).** 설계는 "MST → 여분 간선 → 척추 배치" 순서였는데, 실제로는
**척추를 먼저 뽑고 그래프를 거기에 맞춘다.** 여분 간선이 지름을 3~4방으로 줄여, 완성된 그래프에서
최단경로로 척추를 찾으면 6방을 만들 수 없었다. 함께 확정된 세 가지:

- **회복의 샘은 척추에 놓지 않는다.** 척추에 하나 놓으면 회복량 20 이 공짜로 얹혀 여유가 15 가 아니라
  35 가 됐다(365일 실측). 척추 밖에만 두면 "샘까지 돌아갈 값이 있나"가 판단거리로 남는다.
  대신 척추 밖에 **최소 하나는 보장**한다 — 확률에만 맡겼을 때 365일 중 87일이 샘 없는 맵이었다.
- **여분 간선 비율은 11~19% 를 뽑아 반올림**한다. 10~20% 를 뽑고 버림하면 실측이 8.97% 로 띠 밖으로
  나간다(버린 간선 78개 중 10% = 7.8 → 7).
- **소모 아이템 축(+3)은 먹는샘물(`ItemKind.freshWater`, 200⭐)**이다. 기존 아이템 중 값과 성격이 맞는
  소모품이 없어 새로 넣었다. 소모는 시도 시작 한 지점(`startDungeonRun(drinkFreshWater:)`)에서만 —
  소모와 예산 계산이 갈라지면 마셨는데 예산이 안 오르거나 그 반대가 된다.

**안개는 필수다.** 방 종류는 들어가기 전까지 숨긴다. 처음부터 다 보이면 앉은 자리에서 답이 나와
퍼즐이 성립하지 않는다.

## 시도 진행

`DungeonRun` — 순수 구조체이고 시각(`Date`)을 쓰지 않는다. 맵은 날짜 키로, 시도는 순수 함수로
결정된다.

- 상태: 현재 방, 남은 체력, 밝혀진 방 목록, 사용한 회복 샘, 로그 줄, 단계(탐색 중 / 클리어 / 실패)
- **이동 입구를 하나로 둔다** (`move(to:)`): 인접 검증 → 복도 길이만큼 체력 차감(1~3) → 방 내용 적용 →
  체력이 0 이하면 실패, 보스 방에서 살아남으면 클리어. 판정과 클램프가 여기 한 곳에만 있어야 한다
  (경험치 클램프 입구를 하나로 모은 #81 과 같은 이유 — 입구가 여러 개면 한 곳만 고치고 끝난다).
- 회복의 샘은 한 번만 쓰인다. 아니면 샘과 옆 방을 왕복하며 체력을 무한히 채울 수 있다.

## 저장 상태

`CompanionStore` 세이브에 `DungeonProgress` 하나가 붙는다.

```
DungeonProgress {
  dayKey: String                // 값이 바뀌면 전부 리셋
  cleared: Bool                 // 오늘 클리어했나
  rewardPaid: Bool              // 정산했나 — 재지급 차단
  remembered: [Int: RoomKind]   // 시도 사이 남는 맵 기억
}
```

- 리셋은 자정 타이머가 아니라 **키 비교**다(`MissionBoard` 와 같은 방식). 날짜가 바뀐 첫 기록에서
  비운다. 백그라운드 작업도, 자정에 깨어날 이유도 없다.
- **시도 중 상태(현재 방·남은 체력)는 저장하지 않는다.** 팝오버를 닫으면 시도만 버려지고 맵 기억은
  남는다. 저장 대상을 늘리면 이상 상태 복구 경로가 그만큼 늘어난다.
- 무결성 해시 입력(`canonical`)은 `remembered` 를 **키로 정렬해서** 넣는다. 사전 순회 순서에 기대면
  같은 상태가 실행마다 다른 문자열을 내서 정상 세이브가 무작위로 조작 판정된다(`docs/reference/defect-log.md`
  에 이미 있는 함정).
- 손편집 방어(`normalize()`): 오늘 맵에 없는 방 번호는 버리고, `rewardPaid` 가 참이면 `cleared` 도
  참으로 맞춘다.

정산은 `settleDungeonClear()` 한 곳에서 한다 — `rewardPaid` 가 거짓일 때만 별의조각 1,000 을 주고
알림을 띄운다. 그 뒤 재플레이는 보상 없는 연습으로 열려 있다.

## 화면

`UI/DungeonView.swift`. 팝오버 폭 360 · 높이 780 을 전부 쓰고, 체육관 리그와 같이 탐색 플래그
(`nav.showDungeon`)로 다른 화면 위에 올라온다. 타일 지도 없이 글로만 그린다 — 360pt 폭에 지도를
넣으면 아무것도 읽히지 않는다.

**방마다 고정 이름을 준다(2026-08-24).** 첫 구현은 출구를 "미탐사 · 2" 로만 그렸는데, 실제 맵에서
한 방의 출구가 최대 8개이고 방위도 겹쳐(오늘 맵은 "남동" 출구가 세 개) **줄이 글자까지 똑같아진다.**
방문 순서를 고르는 퍼즐인데 방을 식별할 수 없으면 찍기가 된다. 이름은 날짜 seed 로 결정론 배정하고
**안개와 무관하게 항상 보여 준다** — 이름은 방 종류를 흘리지 않으므로 퍼즐이 깨지지 않고, 시도 사이
맵 기억("이끼 낀 방이 샘이었다")이 이름에 붙는다. 이름 후보는 종류를 암시하지 않는 중립 명사 16개
(방 14개보다 많아 한 맵에 중복이 없다).

```
[헤더]  오늘의 던전 · 돌기둥 방
[활력]  ▓▓▓▓▓▓░░░░░░ 53/105          기억 4/14 · 이번 시도 4방
[서술]  교전이다. 북쪽에서 물소리가 난다. 아직 어두운 길이 3개.
[출구]  새 길
          ↘ 모래 방      · 남동 · 미탐사        −1
          → 마른 우물방  · 동 · 미탐사          −2
        되돌아가기
          ↘ 낮은 굴      · 남동 · 빈 방         −2
[지나온 길]  그림자 방 −2 → 좁은 굴 · 교전 −24 → 낮은 굴 · 빈 방 −2
```

- **새 길 / 되돌아가기를 나눈다.** 섞으면 무엇이 처음 가는 길인지 안 보인다. 둘 다 통로 비용
  오름차순이고, 새 길이 4개를 넘으면 접는다(시작 방은 8개까지 나와 목록이 화면 절반을 먹는다).
- **통로 비용만으로 쓰러지는 길은 붉게** 표시한다. 방 내용은 들어가야 알 수 있으니 통로만 본다.
- **방 카운터는 기억과 이번 시도를 갈라 쓴다.** 하나로 합치면 지난 시도 기억까지 세어 시작하자마자
  "8/14" 로 뜨고 이번 판 진행도로 읽힌다.
- **지나온 길은 방 단위 한 줄**이다. 낱개 이벤트를 그대로 쌓으면 `−24` 가 어느 방 값인지 안 보인다.

전투는 로그 한 줄이다 — 결정론이라 보여 줄 선택이 없고, 배틀 화면으로 넘어가면 던전 흐름이 끊긴다.
실패하면 하단이 "다시 도전" 버튼 하나로 바뀐다. 문구는 기존과 같이 한국어·영어·일본어 세 언어를
`Localization.swift` 에 넣는다.

**계산은 뷰에 두지 않는다.** 방위·이름 슬롯·게이지·출구 분류·서술 재료는 순수 파일
`Core/DungeonNarration.swift` 에 있고 `test-gate.sh` 의 `LOGIC_CORE` 에 들어간다. 뷰에 두면 목업의
줄들이 커버리지 집계 밖에 남아, 화면이 설계의 절반인 채로 게이트가 초록이 된다(실제로 그렇게 나갔다 —
`defect-log.md` 참조).

집계에서 조용히 빠져 무테스트로 나갈 수 있다.

## 테스트 범위

- 같은 날짜 키 → 같은 맵(결정론), 다른 날짜 → 다른 맵
- 모든 방이 시작 방에서 도달 가능(연결성)
- **365일치 날짜 키를 전수로 돌려 기본 예산 100 으로 클리어 가능**한지 확인 — 구성적 생성이 실제로
  보장하는지를 잠그는 핵심 테스트다. 하루짜리 콘텐츠라 클리어 불가능한 맵 하나가 그날을 통째로 없앤다.
- 되살린 간선 비율이 10~20% 안
- 안개: 들어가기 전에는 방 종류가 밝혀지지 않는다
- 체력 0 → 실패, 보스 방 생존 → 클리어
- 보상은 첫 클리어만 — 두 번째 클리어는 0
- 날짜 키가 바뀌면 기억·클리어·정산 플래그가 모두 리셋
- 회복의 샘 재사용 불가
- 화면 계산(`DungeonNarration`): 방 이름이 날짜별 결정론이고 한 맵에 중복 없음, 이름 생성이 맵 생성을
  흔들지 않음, 게이지가 0·만피 두 끝을 흐리지 않음, 출구가 새 길·되돌아가기로 갈리고 비용 오름차순,
  안개 누출 없음(밝혀지지 않은 방의 정체·마신 샘 여부가 서술과 출구에 안 새는지), 지나온 길이 통로
  비용과 방 내용을 제 방에 붙임(**빈 방 두 칸 연속**이 트리거)

새 조건 분기를 넣을 때는 커버리지 퍼센트를 증거로 삼지 않는다. `xcrun llvm-cov show … --show-regions`
로 해당 블록이 `^0`(한 번도 실행되지 않음)이 아닌지 직접 본다 — 줄 커버리지는 조건만 평가되면
실행으로 세기 때문에 블록이 한 번도 돌지 않아도 통과한다.

## 범위 밖 (후속)

**1:1 레이스.** 같은 날짜 맵을 두 사람이 같은 방에서 동시에 출발해 먼저 클리어한 쪽이 이긴다.
맵은 공유된 날짜 seed 에서 나오므로 주고받을 것은 진행 상황과 점수뿐이고, 방·로비·관전은
`MultiplayerRoomCenter` / `BattleCenter` 에 이미 있다. 그때 정할 것 두 가지: 출발은 반드시 동시여야
한다(오늘 맵을 이미 푼 사람이 경로를 그대로 알려줄 수 있다), 랭크 반영은 그날 첫 레이스만
(날짜 키가 각자 로컬 시계 기준이다).
