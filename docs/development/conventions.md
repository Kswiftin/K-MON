# 개발 규약

## 구조와 책임

- `Sources/PokeTokenBar/Core/`: 게임 규칙, 저장 상태, 통신, 터미널 제어 등 핵심 동작.
- `Sources/PokeTokenBar/UI/`: macOS 화면과 사용자 입력.
- `Tests/PokeTokenBarTests/`: XCTest 테스트.
- `Tests/PokeTokenBarLocalTests/`: swift-testing 테스트.
- `scripts/`와 `Tools/`: 빌드·검증·배포 도구.

변경할 기능의 기존 구현과 [기술 참조](../README.md#기술-참조)를 먼저 읽습니다. 같은 규칙을 화면과 터미널에 각각 구현하지 않고 책임을 가진 계층에서 공유합니다. 터미널 조회는 읽기 전용이며, 상태 변경은 메뉴바 앱에 요청합니다. 세부 계약은 [터미널 프런트엔드](../reference/terminal-frontend.md)를 따릅니다.

## 언어와 사용자 경험

앱 화면·코드 주석·문서는 한국어로 씁니다. 코드 식별자·API 이름·CLI 명령·에러 문자열은 원문을 유지합니다. 데이터의 이름·설명과 이전 세이브 처리 규칙은 [한국어 전용 안내](../reference/korean-only.md)를 따릅니다.

UI 변경은 PR에 이전과 이후의 동작을 설명합니다. 스크린샷·GIF는 선택이며, 기존 `assets/` 이미지를 매 PR이나 릴리스마다 재생성하지 않습니다. 이미지가 낡았으면 해당 파일과 달라진 동작을 알리고, 새 이미지 제작은 별도 요청으로 진행합니다.

## 검증

동작이 바뀌면 그 조건을 재현하는 테스트를 추가하거나 수정합니다. 결함 수정은 원인을 확인하고 같은 패턴의 사용처를 점검합니다. 저장·통신·동시성 등 과거 결함과 관련된 변경은 [결함 기록](../reference/defect-log.md)을 참고합니다.

실행 명령과 로컬 검증의 한계는 [개발 환경과 검증](setup.md#테스트와-ci)을 따릅니다. 문서만 바꾼 경우에는 상대 링크, 이미지 경로, 명령·파일명의 유효성, 안내 간 일관성을 확인하고 PR에 검증 범위를 적습니다.

## 문서 배치

사용자가 실행·설정할 내용은 `docs/guides/`, 개발과 배포 절차는 `docs/development/`, 참여·운영 정책은 `docs/community/`에 둡니다. 구현 계약과 과거 설계 기록은 `docs/reference/`에서 유지합니다. 새로운 공개 문서는 [문서 목록](../README.md)에 연결합니다.

README는 소개와 시작 안내를 유지하고 세부 규칙은 담당 문서로 연결합니다. 공개 정책의 본문은 한 곳에서 관리하고, 루트의 안내 문서는 해당 본문으로 연결합니다. 로컬 작업용 스펙·계획은 `docs/plans/`, `docs/specs/` 등 Git에서 제외된 경로에 두며 커밋하지 않습니다.
