# 보안 정책

## 대응 범위

보안 수정은 최신 정식 릴리스를 우선 대상으로 합니다. 이전 버전에 대한 별도 백포트는 보장하지 않습니다. 개발 버전이나 `main`에서 발견한 문제도 제보할 수 있으며, 제보 시 버전·커밋을 적어 주세요.

인증 정보 노출, 악성 LAN 메시지 처리, 세이브·캐시·CLI 요청의 접근 제어, 업데이트·서명 검증처럼 사용자 데이터나 실행 환경에 영향을 주는 문제를 다룹니다. 일반 버그와 사용 문의는 [기여 가이드](contributing.md)의 이슈 경로를 이용합니다.

## 비공개 제보

취약점의 상세 내용과 재현 코드는 공개 이슈나 PR에 올리지 않습니다.

1. 저장소의 [Security → Advisories](https://github.com/Kswiftin/K-MON/security/advisories)를 엽니다. **Report a vulnerability**가 표시되면 비공개 신고를 제출합니다.
2. 버튼이 없다면 공개 이슈에는 **보안 제보용 비공개 연락 방법 요청**만 남깁니다. 영향받는 기능, 취약점 유형, 재현 코드, 로그나 인증 정보는 넣지 않습니다. 메인테이너가 안내한 비공개 경로로 상세 내용을 전달합니다.

이 절차는 [GitHub 비공개 취약점 신고 안내](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)를 따릅니다. 신고 기능의 제공 여부는 저장소 설정에 따라 달라집니다.

제보에는 다음 정보를 포함합니다.

- 앱 버전·소스 커밋, macOS 버전과 관련 설정.
- 재현 조건과 최소 단계, 기대 동작과 실제 결과.
- 영향을 받는 데이터·기능과 예상 영향.
- 가능한 해결 방향과 후속 연락 방법.

실제 사용자의 세이브·대화·인증 정보 대신 익명화한 최소 예제를 사용합니다. 다른 사람의 기기나 LAN 서비스를 동의 없이 대상으로 삼지 않습니다.

## 처리와 공개

메인테이너는 비공개 경로에서 접수 여부와 추가 정보 요청을 전달하고, 재현·영향 평가·수정·검증을 진행합니다. 공개 시점과 제보자 표기는 제보자와 협의합니다. 수정 배포 후 사용자에게 영향, 대응 방법과 수정 버전을 알리되 악용 가능한 세부 정보의 공개 시점은 별도로 조율할 수 있습니다.

작은 프로젝트이므로 고정된 응답·수정 기한이나 보상 프로그램을 보장하지 않습니다. 진행 상황은 같은 비공개 경로로 문의해 주세요.
